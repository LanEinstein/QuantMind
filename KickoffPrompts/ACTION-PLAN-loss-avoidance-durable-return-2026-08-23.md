## 3. 系统目标的重新定义:「稳定盈利」翻译成可检验判据

### 3.1 目标形态(诚实的天花板)

以 owner 资金量级、A 股、L1 数据、不加杠杆:

> **长期年化接近市场(不承诺跑赢),组合最大回撤约为市场的一半(≤20—25% vs 全市场熊市 40—50%),
> 之上叠加制度红利层每年约 2—4% 的正贡献(政策依赖,会衰减),
> 空仓/现金部分永远不低于货基地板(≈1.3—1.6%)。**

SLV-1 样本内形状(MDD 19.6% vs 46%)就是这个量级的实证。
比这更乐观的目标,本计划给不出"这次不一样"的理由,所以不给。

### 3.2 四要件的判据化

| 要件 | 判据 | 认证方式 |
|---|---|---|
| ① 正期望收益来源 | R 层:每条 sleeve 独立预注册科学门(净盈>0/熊市累计≥0/MDD≤20%/胜随机 placebo t≥2)+ 前向 8 期存活。Z 层:免判据(免费期权,只记账,见 §4.2) | sleeve=样本内门+前向 kill-switch;Z=逐笔落账披露 |
| ② 熬得过的回撤 | 组合级前向实现 MDD ≤ 25% 硬监控(各 sleeve 各自 kill 0.25;组合层披露) | 前向逐日盯市,模拟盘账本 |
| ③ 成本吃不掉收益 | 每笔按真实仓位名义额计费(万 1.5+5 元地板+印花税+滑点);月度换手 ≤ 0.1(sleeve 实测 0.01) | 预注册写死费用模型 |
| ④ 组件独立 | 收益来源分线记账(R1/R2/Z1/Z2/D),月度披露相关性;**诚实声明:两条 sleeve 都是 A 股多头,资产层相关性高,真正独立的只有 Z 层与现金地板** | 模拟盘分线账本 |

**FAIL 报 FAIL**:任何一层 kill-switch 触发即如实停,不调阈值续跑。

### 4.1 R 层:风险溢价 sleeve

外部证据综述(A 股,2023—2026):

| 因子 | 判定 | 角色 |
|---|---|---|
| 红利(现有 SLV-1) | **拥挤但补偿仍在**(股息率 6.4% vs 十年国债 1.6%,历史极宽利差;但 2026-03..06 红利低波指数拥挤平仓回撤 −13.7% 已示范崩法) | 现有 sleeve,前向超额预期应下调,40% 现金 buffer 正在承重 |
| **质量(盈利腿)** | **持久、温和、不拥挤**;A 股证据下只有 profitability 子腿稳定,投资/资产增长腿弱;与红利正交性最好(高 ROE 稳盈利名单含消费/医药/制造,不只银行煤炭) | **SLV-2 首选** |
| 低波 | 溢价真实但与红利重叠(主动收益相关约 0.5—0.7) | 只作过滤器(SLV-1 已含) |
| 小市值 | **陷阱**(退市新规左尾+2024-02 微盘流动性危机+2026-06 再演) | 反向过滤:剔除底部尾巴(已在做) |
| 价值 E/P | 不明朗,与红利重叠 | 只作廉价度过滤 |
| 动量 | A 股不可用(反转主导) | 不用 |

**R2 = SLV-2 质量 sleeve**(本计划最大的一块研究工作):
- 构造沿用 SLV-1 已验证的架构:防御宇宙 gates → **单一简单盈利质量选择规则**(候选:ROE 稳定性
  或 毛利率×低应计,预注册时定死一个)→ top-5 等权 → ≥40% 现金 buffer → 20 日调仓。
- **重叠纪律**:排除 SLV-1 当期持仓,披露行业/持仓重叠度。
- 路径:预注册 → 实现 → 科学门一次(同 placebo 机器)→ PASS 则独立前向注册(自己的 kill-switch),
  FAIL 则封存,R 层维持单腿。
- **为什么值得做**:唯一同时满足"证据持久+不拥挤+与现有 sleeve 正交+机器全现成"的候选;
  失败成本 = 一次预注册研究。
- **为什么不是可转债**:见 §4.4。

### 4.2 Z 层:制度红利(完全未开采,本计划第一个动工点)

| 候选 | 2024—2026 实况 | 判定 |
|---|---|---|
| **A 股市值打新** | 2025:114 只 IPO **零破发**,首日均涨 +254%;2026H1:+280.7%(2017 以来最高),中签率 0.028%(五年新低)。按 20 万市值年化约 3.5—7%(高方差,泊松式 1—3 签/年) | **开工**。sleeve 持仓本身就是打新市值——白送的彩票 |
| **可转债打新** | 2025:首日均涨 +37% 零破发;2026:+53% 仍零破发;信用申购零成本,期望约 1,000—1,800 元/年 | **开工**(顺手) |
| **现金地板** | 货币 ETF ~1.0—1.1%;逆回购+同业存单梯 ~1.3—1.6%;季末 GC001 冲高 2—3% | **开工**(卫生习惯;常年 ≥40—60% 现金,直接可拿) |
| 北交所打新 | 2026H1 获配 100 股平均需 626 万资金 | 不做(规模死) |
| ETF/LOF/QDII 折溢价 | 套利需一级市场额度(恰是被暂停的);场内价差 <0.1% 盘中被做市商吃掉 | 不做(只留防御规则:溢价 >2% 的 QDII 不买) |
| 指数调样抢跑 | 成分可预测→指增基金提前数周布局;学术证据=临时价格压力+回归 | 不做 |
| 要约收购套利 | 活着但每年零星几单、需逐单读公告,无干净数据端点 | 不做(非系统化) |
| 分红除权套利 | 差别股息税+除权日有效定价,早已死 | 不做 |

**Z 层的验证哲学:不回测。** 打新与现金地板是**免费期权/无风险地板**,盈利性证据是外部的、当下的;
回测它们测的是**政策制度本身**(IPO 节流),不是信号,对决策没有增量。
代替回测的是三样东西:
1. **参与协议预注册**(哪些新股申购、中签后何时卖——固定纪律:上市首日卖出,不做择时);
2. **逐笔落账**(模拟盘单列 Z 线 P&L,让贡献可见、衰减可见);
3. **政策依赖的 kill 规则**(滚动 20 只新股破发率 > 20% → 自动停发打新提醒,上报 owner)——
   2021—2022 破发潮就是政策正常化的样子,这个红利的死法是已知的。

### 4.3 D 层:防守纪律(语料的正确用法)

16 张缺买点触发器的卡里,防守类最强(卡 4 是 18 张里唯一 `stable_core`)。
它们不造买点,**在已有组合上做消融**:

- **MD-1(首个消融)= P-B 硬止损**:在 SLV-1 科学门窗口的**重放**上加一条止损规则——
  持仓 N 日收益跑输**全市场横截面中位数**(市场基准从面板自构,本地无指数历史)超过阈值 X
  即次日开盘卖出("反常"=相对弱势,非绝对跌幅;绝对跌幅在熊市会把整个组合止损掉)。
  **预注册单问题**:加上它,MDD 降不降、净盈掉多少?
  **事件不足条款预注册**:sleeve 月调仓 top-5、125 个月仅 9 次换手,止损事件可能太少;
  触发事件 < K(预注册定,量级 ~30)→ 裁决"事件不足",封存,不调参重跑。
  结果只喂给**认证后**的 SLV-1.1 spec 决策;运行中的前向认证一字不碰。
- **卡 4 / 卡 9(禁亏损补仓、禁浮盈加仓、默认不做 T)= 行为护栏,不回测**:
  它们约束的是 owner 的手工行为,我们的账本上没有反事实数据可测
  (sleeve 本来就不补仓)。落地方式:写进飞书建议的固定护栏文案与对账逻辑
  (owner 回报"补仓了亏损股"时系统如实记账但提示违反 P-B/卡4)。
- **卡 6(退潮降暴露)明确排除**:它是组合层择时,与择时 overlay 永久关门直接冲突,
  且 B1(regime derisk)已 FAIL。不因为它出自语料就豁免。
- **卡 11 / 卡 12(下跌先诊断、兑现窗口分层退出)**:推迟——组合事件数不足以支撑消融;
  等组合运行一年积累事件后再评估,或永远作为 owner 人工判断的参考卡。

### 4.4 可转债双低:登记为**条件候选**,现在不做

调研结论:结构上还活着(T+0、无印花税、EOD 轮动本来就是散户玩法、50 万量级远低于容量上限),
但**2026 年是该资产历史上最贵的进场点**——存量 8,700 亿(2023 峰值)→ 5,005 亿(2026-06-30),
2025 年强赎退出 173 只,90 元以下低价债 2024 年已绝迹,2024 年信用尾部(搜特/蓝盾/岭南)已示范。
预期回报中个位数、回撤风险 15—25%,不是回测时代的 15% CAGR。

**处置**:不开工,但**预注册一个进场条件**放进季度检查:
当全市场可转债**中位价格回落到 115 元以下**或双低分位回到历史中位以下时,
再立项 SLV-CB 研究(数据端点已验证可用,届时需新增 cb_* 摄取线)。
条件写死在这里,就不存在"跌了才追认"的事后选择。

## 5. L1 约束下的建议产生与推送设计(任务书 §1.3 六问逐条回答)

现状参考:`scripts/sleeve_trial_daily.sh`(17:40 cron)→ `defensive_sleeve_forward.py` →
`push_sleeve_advisory.py`(renderer 组文案,display-only,per-asof 去重)。
该链路已实发跑通,但**当前逐交易日推送**(asof 每日推进→每日一条),与"静默是默认"冲突,
MI-1 里改。

**① 建议在什么时点产生?** 盘后:cron 17:40(Tushare 日线约 16:30 落地)生成并当晚推送;
owner 次日开盘后执行。不做盘前重算(L1 下盘前没有新信息)。

**② 有效期与失效条件?** 建议有效期 = 次一交易日全天。逐条失效条件写进推送文案:
- 该股停牌 → 该笔作废,当晚重算;
- 买入建议遇一字涨停开盘 → 不追(P-A),该笔顺延至当晚重算;卖出遇一字跌停 → 挂单等待,连续 3 日不能成交上报 owner;
- 开盘价偏离建议基准收盘价超过 **±5%** → 该笔作废,当晚以新收盘重算(sleeve 是慢因子,容忍度可以宽;止损类建议不设此豁免——P-B 硬触发不等确认);
- kill-switch 状态变为 KILLED → 全部未执行建议立即作废,只推"停止执行"通告。

**③ 建议必须包含什么?** 个股(代码+名称)、方向、目标权重与当前模拟盘权重的差值、
所属层与触发规则(一句话理由)、基准收盘价、失效条件、未成交处置("没买到不用管,明晚我会重算")、
kill-switch 状态一行、固定护栏文案(不补仓亏损股/不梭哈/≥40% 现金)。
措辞总分结构、通俗自然,禁执行动词作指令(display-only,无 QM- id)。

**④ 什么情况下不推送?** **静默是默认**。只在五种时刻推送:
(a) sleeve 调仓日且目标持仓与当前模拟盘有差异;(b) kill-switch 状态变化(含 KILLED);
(c) D 层止损触发(SLV-1.1 启用后);(d) 打新日提醒(当日有可申购新股/转债,一条合并);
(e) owner 对账追问(缺成交价等)。
其余日子:pipeline 照跑、状态照写,**不发消息**。
实现上把 push 的去重键从 per-asof 改为 **(内容哈希, 事件类型)**——内容没变就不发。

**⑤ 实际成交价与系统假设不一致怎么对账?** owner 自由文本回报("买了 5000 股,成交 12.3")→
LLM 解析 → 模拟盘按 **owner 实际成交价** 落账(owner 的账是真相,系统假设价只用于研究侧账本);
缺要素(价格/数量)追问一次;次日收盘前无回报 → 默认未成交,当晚重算重推。
研究侧账本(前向认证用)与镜像账本(owner 真实状态)**分开记**,前者永远用预注册口径价,
两本账的偏差月度披露一行(这就是执行时点偏差的实测续测)。

**⑥ 建议颗粒度?** sleeve:20 交易日一次调仓,期间只有失效重算,无日频建议;
止损:事件驱动(触发才有);打新:当日事件(合并成一条);现金地板:一次性协议文本+季末提醒,
不做日频。**L1 数据下没有任何日内/高频建议,永远没有。**

## 9. 风险与坦白(这套计划最可能死在哪里)

1. **打新红利是政策租金**:零破发是 IPO 节流的人造产物;节流一松,2021—2022 破发潮就是模板。
   对策已内建(滚动破发率 kill 规则),但要诚实:Z 层最大的一块贡献随时可能政策性归零。
2. **红利拥挤崩**:2026-03..06 红利低波 −13.7% 已经示范过 SLV-1 所在赛道的崩法。
   SLV-1 前向第 1 期 −3.4% 就是这个环境的产物。kill-switch 是承接机制;
   若 SURVIVING 失败,R 层从头再来,本计划 §4.1 的因子地图是重来的起点。
3. **SLV-2 科学门可能 FAIL**:质量溢价"温和"意味着可能过不了 placebo 门。
   FAIL 则 R 层单腿运行——计划仍然成立,只是第④件事(组件独立)继续缺位。
4. **组件独立性天生有限**:两条 sleeve 都是 A 股多头,系统性熊市会一起跌;
   真正独立的只有 Z 层(政策租金)与现金地板。本计划不假装解决了这一点,
   只靠 ≥40% 现金 buffer 和 MDD 上限硬扛。
5. **消融可能"事件不足"**:sleeve 太稳(125 月 9 次换手),P-B 止损可能无足够事件可测。
   预注册里写死这个出口,防止为了出数字而改口径。
6. **对账闭环的 LLM 是新故障面**:owner 自由文本 → 账本更新,解析错了账就错。
   MI-1 的对账演练(owner 参与一次)是唯一真实的验收;错账的兜底是"owner 的下一条消息永远能改"。
7. **执笔者偏差**:本计划的研究判断由 Claude 主执行+Codex 讨论得出,没有第三方;
   调研引用的外部数字(打新收益率、CB 估值)未逐一复核原始数据,
   MZ-1/§4.4 落地前会用本地 Tushare 数据把关键数字复算一遍(new_share 破发率、cb 中位价)。
