## 决策摘要

QuantMind 第一阶段 MockBroker 持久化与日切调度采用 **混合 delta+EOD 快照 + 双 Applier + 条件自动恢复 + 专用 BrokerScheduler** 架构,满足 P0-1 唯一账户镜像 + P0-4 状态机守门 + P0-5 reset_to_snapshot 唯一覆盖入口 + P0-6 每日 EquityPoint 必写 + P0-7 熔断状态独立 collection + P0-8 MiroFish 17:00 盘后复盘多决策的协同要求:

1. **混合 delta + EOD 快照**:`broker_events` collection(append-only delta;每个状态转移一条记录)+ `broker_snapshots` collection(每交易日 16:00:35 EOD 全量 + ReconciliationApplier / 模式切换触发额外快照);通过 Mongo multi-doc transaction 跨 collection 原子写入;启动从最新 snapshot + replay delta 恢复。

2. **双 Applier 类**:`ReconciliationApplier::reset_to_snapshot`(P0-5 红线 12 唯一全量覆盖入口;reconciliation_ticket 用户三选一裁定后调)+ `ExecutionReportApplier::apply`(P0-4 增量,状态机守门 DISPATCHED → FILLED/AMBIGUOUS/REJECTED/EXPIRED + 更正 + 盘后补录);两类都在 Mongo multi-doc tx 内同步写 broker_events + 必要时 broker_snapshots。

3. **条件自动重启恢复**:启动时读取最新 `broker_snapshots`,若 `captured_at` 距今 ≤3h 且 checksum 财务全状态(`cash` + `frozen_cash` + `positions(code, volume, cost_price)` + `open_orders` + `trades_today`)SHA256 验证通过 → 自动 replay delta 直至最新 event_id;否则 alert 入运维裁定通道(CLI 工具 + 飞书系统告警),禁止盲目自动恢复(继承 fail-closed for data corruption 原则)。

4. **专用 BrokerScheduler(APScheduler)**:与现有 `DataScheduler` / `AnalysisScheduler` 同技术栈不同实例;职责单一(EOD chain + advance_day + recovery snapshot);三个 cron job:
   - `eod_pipeline`(16:00:00 mon-fri Asia/Shanghai;sequential coroutine 内部 await 调度 execution_cutoff → chase_poller_terminal → reconciliation_request → acceptance_report → recovery_snapshot)
   - `mirofish_postclose`(17:00:00 mon-fri Asia/Shanghai;独立 cron;与 EOD chain 无状态依赖)
   - `advance_day`(次交易日 09:00:00 mon-fri;内置节假日 YAML gating)

5. **EOD chain 失败处理**:核心路径(execution_cutoff → chase_poller → acceptance_report → snapshot)任一失败 → 1 次重试 → 仍失败 → alert 入运维 + **冻结次日买卖类 InstructionPlan 路由**(与 P0-1 切换冻结 / P0-5 ticket 冻结 / P0-7 熔断冷却 / P0-8 DataQualityState 早返并列为第五种买卖类路由冻结来源);17:00 MiroFish best-effort 失败 → log + alert + skip(不影响后续路由)。

6. **跨 collection 原子性**:Mongo multi-doc transaction 强约束;**前置实施期任务**:现有 mongod 单实例需迁移到 replica set(`replSetInitiate` 单节点 RS 即可);启动期检查 `db.runCommand({ismaster: 1})` 返回 `setName` 不为空,否则 fail-closed 拒绝启动 BrokerScheduler。

7. **schema 版本与不兼容变更**:`BrokerEvent` / `MockBrokerSnapshot` 含 `schema_version: int = 1` 字段;**第一阶段不实现 auto-migration**(继承"避免 backwards-compat shim"原则);schema 破坏式变更必须先走 `P1-2.A-amendment-{date}-schema-bump.md` + 全量 re-init(模式切换流程触发清空)。

from pydantic import BaseModel, ConfigDict, Field

class BrokerEvent(BaseModel):
    """broker_events collection 单条记录。append-only,严禁 update / delete。"""

        "ORDER_FILLED",            # 成交(扣现金 + 加持仓 + 记 Trade)
        "ORDER_PARTIALLY_FILLED",  # 部分成交(P0-4 形态二)
        "ORDER_REJECTED",          # RiskEngine 14-check 拒绝(解冻现金)
        "ORDER_EXPIRED",           # P0-3 valid_until 触发(解冻现金)

#### 1.2.3 checksum 计算口径

```python
# backend/broker/persistence/checksum.py(实施期新增)

import hashlib
import json

def compute_snapshot_checksum(snap: MockBrokerSnapshot) -> str:
    """财务全状态 SHA256;启动期条件自动恢复依赖。"""
    canonical = {
        "cash": round(snap.cash, 2),
        "frozen_cash": round(snap.frozen_cash, 2),
        "positions": sorted(
            [(p.code, p.volume, round(p.cost_price, 4), p.today_bought_volume) for p in snap.positions]
        ),
        "open_orders": sorted(
            [(o.instruction_id, o.status) for o in snap.open_orders]
        ),
        "trades_today": sorted(
            [(t.trade_id, t.code, t.volume, round(t.price, 4)) for t in snap.trades_today]
        ),
    }
    blob = json.dumps(canonical, sort_keys=True, separators=(",", ":"), ensure_ascii=False)
    return hashlib.sha256(blob.encode("utf-8")).hexdigest()
```

```python
class ExecutionReportApplier:
    """P0-4 五种回报形态 + 更正 + 盘后补录的增量入口。"""

    def __init__(
        self,
        broker: MockBroker,
        instruction_repo: InstructionPlanRepo,
        event_repo: BrokerEventRepo,
        mongo_client: AsyncIOMotorClient,
        state_machine: InstructionPlanStateMachine,  # P0-4 守门函数
    ): ...

    async def apply(
        self,
        plan: InstructionPlan,
        report: ExecutionReport,
    ) -> InstructionPlan:
        """单 Mongo 多文档事务内:
        1. new_plan = state_machine.transition(plan, report)  — DISPATCHED → FILLED/PARTIALLY_FILLED/AMBIGUOUS/...
        2. 若 new_plan.status ∈ {FILLED, PARTIALLY_FILLED}:
              broker.apply_fill(plan, report)
              event_repo.insert(BrokerEvent(event_type='ORDER_FILLED' / 'ORDER_PARTIALLY_FILLED', ...))
           若 new_plan.status == 'AMBIGUOUS':
              **broker 不变**(P0-4 红线 1 fail-closed)
              event_repo.insert(BrokerEvent(event_type='ORDER_AMBIGUOUS', ...))
           若 new_plan.status == 'REJECTED':
              broker.unfreeze_cash(plan)
              event_repo.insert(BrokerEvent(event_type='ORDER_REJECTED', ...))
           若 new_plan.status == 'EXPIRED':
              broker.unfreeze_cash(plan)
              event_repo.insert(BrokerEvent(event_type='ORDER_EXPIRED', ...))
        3. instruction_repo.update(new_plan)
        事务失败 → broker 状态不变 + 抛 ExecutionApplyError。
        """

    async def apply_correction(self, plan: InstructionPlan, correction: ExecutionCorrection) -> InstructionPlan:
        """P0-4 更正路径(从终态出发);broker 反转上一笔 fill + 应用更正后 fill;事务保护。"""

    async def apply_post_close_backfill(self, plan: InstructionPlan, backfill: PostCloseBackfill) -> InstructionPlan:
        """P0-4 盘后补录路径(对未回报指令);仅允许 EXPIRED/AMBIGUOUS/DISPATCHED → FILLED;每个 instruction_id 仅一次。"""
```

### 1.4 重启恢复条件自动逻辑

#### 1.4.1 启动期决策树

```python
# backend/broker/persistence/restorer.py(实施期新增)

async def restore_broker_on_startup(
    broker: MockBroker,
    snapshot_repo: BrokerSnapshotRepo,
    event_repo: BrokerEventRepo,
    config: RestoreConfig,
) -> RestoreOutcome:
    """启动期调用一次。返回 RestoreOutcome 决定后续路径。"""

    latest = await snapshot_repo.find_latest()
    if latest is None:
        # 首次启动 / mongod 全空
        return RestoreOutcome(action="MODE_SWITCH_RESET", reason="no_snapshot_found")

    age_seconds = (now_in_shanghai() - latest.captured_at).total_seconds()
    if age_seconds > config.max_snapshot_age_seconds:  # 默认 3 * 3600 = 10800
        return RestoreOutcome(
            action="MANUAL_REVIEW",
            reason=f"snapshot_stale({age_seconds:.0f}s > {config.max_snapshot_age_seconds}s)",
            latest_snapshot_id=latest.snapshot_id,
        )

    expected_checksum = compute_snapshot_checksum(latest)
    if expected_checksum != latest.checksum_sha256:
        return RestoreOutcome(
            action="MANUAL_REVIEW",
            reason="checksum_mismatch",
            latest_snapshot_id=latest.snapshot_id,
            expected=expected_checksum,
            actual=latest.checksum_sha256,
        )

    # 自动恢复 + replay delta
    await broker.replace_state(latest)
    delta_count = await _replay_events_since(broker, event_repo, since_event_id=latest.last_event_id)
    return RestoreOutcome(
        action="AUTO_RESTORED",
        reason="snapshot_fresh_and_checksum_valid",
        latest_snapshot_id=latest.snapshot_id,
        replayed_events=delta_count,
    )
```

#### 1.6.2 EOD chain(sequential coroutine)

```python
async def _run_eod_pipeline(self) -> None:
    """16:00:00 启动。核心顺序;任一失败 1-retry → 仍失败 fail-closed alert + freeze 次日买卖类。"""
    if not self._holidays.is_trading_day(today_in_shanghai()):
        return  # 节假日 / 周末 跳过
    try:
        await self._step_execution_cutoff()         # 16:00:00 — P0-4 valid_until 强制 EXPIRED
        await asyncio.sleep(30)
        await self._step_chase_poller_terminal()    # 16:00:30 — P0-5 chase_poller 最后一次扫
        await self._step_send_reconciliation_request()  # 16:00:30 — P0-5 系统主动发对账
        await asyncio.sleep(5)
        await self._step_generate_acceptance_report()   # 16:00:35 — P0-6
        await self._step_write_recovery_snapshot()      # 16:00:35 — 本决策
        logger.info("eod_pipeline_completed", trade_date=str(today()))
    except Exception as exc:
        logger.error("eod_pipeline_failed_first_attempt", error=str(exc), exc_info=True)
        try:
            await self._retry_remaining_critical_steps()
            logger.info("eod_pipeline_retry_succeeded")
        except Exception as exc2:
            logger.error("eod_pipeline_failed_freeze_next_day", error=str(exc2), exc_info=True)
            await self._alerter.alert_eod_failed(reason=str(exc2))
            await self._set_next_day_buy_sell_freeze(reason="eod_pipeline_failed")
```

## 2. 红线(违反即停止)

1. **MockBroker 状态修改入口红线**:任何代码尝试 `broker.replace_state(...)` 或直接 mutation `broker._cash` / `broker._frozen_cash` / `broker._positions[code]` / `broker._trades.append` / `broker._orders[id]` 都属红线违规;**仅允许 ReconciliationApplier / ExecutionReportApplier / advance_day() 三个入口修改**(advance_day 是 broker 自身的方法,但只允许 BrokerScheduler 在 09:00 cron 中调用,严禁其他路径触发)。lint rule 必须 grep `broker._cash =` / `broker._positions\[` / `broker._trades.append` 在 `backend/` 内只在以下白名单文件内出现:`backend/broker/mock_broker.py`(自身实现)+ `backend/broker/persistence/appliers.py`(双 Applier 内部);其他任何位置即红线违规。

2. **broker_events append-only 红线**:`db.broker_events.update_one` / `update_many` / `delete_one` / `delete_many` 在 `backend/` 内永禁出现(仅 retention amendment 落地后允许 truncate by date range)。lint rule 必须为空。

3. **broker_snapshots 不可就地修改红线**:`db.broker_snapshots.update_one` / `update_many` 永禁;新 snapshot 一律 insert(`snapshot_id` 已含 EOD/RECON-{seq}/MODE-{seq} 区分);需要"覆盖"也通过 ReconciliationApplier 写**新一条**而非更新旧的。

4. **Mongo replica set 强约束红线**:`backend/broker/scheduler.py::BrokerScheduler.start` 必须前置检查 `db.runCommand({ismaster: 1}).setName` 不为空;为空即抛 `MongoTopologyError` + 拒绝启动。standalone mongod 启动 BrokerScheduler 视为红线违规。

5. **Mongo 多文档事务包裹红线**:`broker_events.insert_one` 与 `broker_snapshots.insert_one` 在双 Applier 内部必须在同一 `session.start_transaction()` 内执行;任何只插入 events 不插入对应 snapshot(或反之)的代码即红线违规。

6. **schema_version 不可改红线**:`BrokerEvent.schema_version=1` / `MockBrokerSnapshot.schema_version=1` 在 P1-2.A 第一阶段恒为 1;升级到 2 必须先走 `P1-2.A-amendment-{date}-schema-bump.md` + 全量 re-init 流程。运行时强制 `if event.schema_version != 1: raise SchemaVersionError(...)`。

7. **重启自动恢复阈值不可改红线**:`max_snapshot_age_seconds=10800`(3h)+ `replay_max_events_for_auto=10000` 在 P1-2.A 锁定;调整必走 amendment;实施期 lint rule 阻止两常量被覆写。

8. **checksum 财务全状态范围不可改红线**:checksum 必须包含 `cash` + `frozen_cash` + `positions(code, volume, cost_price, today_bought_volume)` + `open_orders(instruction_id, status)` + `trades_today(trade_id, code, volume, price)`;**减少**任一字段即红线违规(漏检漂移会导致 P0-5 对账失真)。**增加**字段需走 amendment(可能触发既有 snapshot checksum 失效,需要全量 re-init)。

9. **EOD chain 顺序不可乱红线**:`_run_eod_pipeline` 内 sequential await 顺序必须为 `execution_cutoff → sleep30 → chase_poller_terminal → reconciliation_request → sleep5 → acceptance_report → recovery_snapshot`;任何尝试并行化 `chase_poller` 与 `acceptance_report` 即红线违规(acceptance_report 依赖 chase_poller 终态)。

10. **17:00 MiroFish 失败不可冻结路由红线**:`_run_mirofish_postclose` catch Exception 后只允许 `alerter.alert_mirofish_failed` + log,**严禁**调用 `_set_next_day_buy_sell_freeze`(P0-8 §1.4 MiroFish 是加分项不是核心,失败不得阻断主路径)。

11. **EOD chain 失败必须冻结次日红线**:`_run_eod_pipeline` retry 仍失败必须调 `_set_next_day_buy_sell_freeze(reason="eod_pipeline_failed")`,严禁"alert 后忽略继续放行";写入 `circuit_breaker_state.eod_pipeline_failed_at`,ModeRouter 与 InstructionPlanBuilder 早返必须 OR 检查此字段。

12. **advance_day 节假日 gating 红线**:`_run_advance_day_if_trading` 必须前置 `holidays.is_trading_day(today)`;严禁周末/节假日触发 T+1 解锁(否则 today_bought_volume 在非交易日提前清零,与真实 A 股 T+1 语义不符)。

13. **BrokerScheduler 单实例红线**:与 P0-2 lark-oapi 长连接同源(继承 P0-2 §2 红线 5 单实例原则);多实例并发 EOD chain 会导致重复 snapshot / 重复 reconciliation_request → 红线违规。实施期通过文件 lockfile(`/var/run/quantmind/broker_scheduler.lock`)守门。

14. **CLI 工具 manual restore 红线**:`backend/broker/cli.py::restore` 必须经 ReconciliationApplier(继承红线 1);严禁直接覆盖 `broker._cash` / 直接 update broker_snapshots collection。

15. **schema 不可降级红线**:`BrokerEvent` / `MockBrokerSnapshot` / `PositionSnapshot` / `OrderSnapshot` / `TradeSnapshot` 是 frozen Pydantic v2 strict + extra="forbid"(继承 P0-3 / P0-7 / P0-10 immutability + LLM-resistance 原则);就地 mutation 红线违规。

16. **LLM 严禁参与持久化路径红线**:`backend/broker/persistence/*.py` 严禁 `import backend.llm.*`(继承 P0-4 §2 红线 2 / P0-5 §2 红线 6 / P0-6 §2 红线 3 / P0-8 §2 红线 7);snapshot 字段值、event_type、checksum 算法、retention 阈值都由确定性代码决定。

17. **第一阶段排除项**:

- 多 mongod 节点 RS(单节点 RS 即可)
- Mongo Change Streams / oplog 触发恢复(留 P1-2.B/C 视需求引入)
