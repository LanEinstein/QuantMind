# P1-2.A amendment(2026-06-12):manual-trade 落地的锁定枚举扩展(AD-005 实施细则)

> 状态:**已锁定**(实施 [`P1-5-amendment-2026-06-12-manual-trade-third-write-endpoint`](./P1-5-amendment-2026-06-12-manual-trade-third-write-endpoint.md) 的具体落地)。
> 父决策:P1-5-amendment-2026-06-12 已授权第 3 写端点 `POST /api/manual-trades`、`ExternalExecutionEvent` 独立域、`ManualTradeApplier` 进镜像(复用 `apply_external_fill` 语义 + append-only broker_event)、renderer「已记录」飞书同步、绩效三分流。本文仅记录为实现这些**已授权行为**而对若干**锁定枚举集**做的最小扩展,使红线扫描 / 成员断言测试不把它们误判为无 amendment 的边界漂移。
> 不动:单一镜像(仅 `apply_external_fill` / `reset_to_snapshot` 两入口)、append-only、单一构造点、LLM 不写决策、127.0.0.1、永禁真实下单、PIT 可复现。

## 1. 锁定枚举扩展(逐项)

### 1.1 `BrokerEventType` + `MANUAL_TRADE_APPLIED`(`backend/broker/persistence/events.py`)
- 新增枚举值 `MANUAL_TRADE_APPLIED = "manual_trade_applied"`。
- **不 bump `BROKER_EVENT_SCHEMA_VERSION`(保持 = 1)**:该事件复用 v1/v2 既有 wire format —— 与 `EXECUTION_REPORT_APPLIED` **完全同构**的「generic delta carrier」(payload 携 `cash_delta` + `positions_delta` + v2 friction 明细 + 复权/铭牌字段),结构未变,故无须迁移既存行。**理由**:bump 常量会令所有历史 v1 行的 `model_validator` 失败(`schema_version != CURRENT` 即 raise),对在跑的持久化数据是破坏性操作;而新增同构事件类型不改 wire format,recovery 学会新 `event_type` 分发即可。
- recovery 新增分发规则(`recovery.py`),逻辑 = `EXECUTION_REPORT_APPLIED` 的 delta 回放(v2 fail-closed 校验保留;trade_date 由 `external_trade_id` 内嵌 `UT-YYYYMMDD-` 解析,与 QM- 同位)。
- **域分离正当性**:手动交易是独立域(codex P0-6「绝不伪造 InstructionPlan」)—— 用专属 event_type 而非给 `EXECUTION_REPORT_APPLIED` 打 tag,使 broker 事件流审计无歧义(用户自主操作 ≠ 系统指令回报)。

### 1.2 `AuditEventType` + `MANUAL_TRADE_SUBMITTED`(`backend/audit/models.py`,类 1 写端点)
- 新增 `MANUAL_TRADE_SUBMITTED = "manual_trade_submitted"`,归**类 1「两(现三)写端点调用」**,actor = `FEISHU_USER`(手动操作仅 feishu_interactive 模式可提交)。
- 锁定审计类型集计数 34/41 → +1。LLM 严禁写 audit 不变。

### 1.3 `FeishuMessageKind` + `MANUAL_TRADE_RECORDED`(第 7 类;`renderer.py`)
- 新增第 7 类 `MANUAL_TRADE_RECORDED = "manual_trade_recorded"`(P1-5-amendment §1.3 已授权「已记录」语义消息)。
- 新 renderer 方法 `render_manual_trade_ack`:**无 QM- 指令号、无成交指令动词**,对抗 `parse_execution_report` 必 `no_pattern_match`(快照测试钉死)。发**决策群**(非告警群);失败 fail-open 不回滚已落账(沿用 U-D12 ack 先例)。
- 既有「membership 恒 6」断言更新为 7,并加该新类的 parser-immunity 对抗测试。

### 1.4 `Trade.origin` + `TradeOrigin`(`backend/broker/models.py`)— 绩效三分流地基
- `Trade` 新增 `origin: TradeOrigin = TradeOrigin.SYSTEM_SUGGESTED`(additive,默认 = 系统建议;既有所有成交路径不传 origin → 默认 system_suggested,**字节级向后兼容**)。
- `TradeOrigin` 三枚举:`SYSTEM_SUGGESTED` / `USER_DISCRETIONARY` / `RECONCILIATION_RESET`(后者无 Trade 行,仅语义保留 + 前端三桶)。
- `apply_external_fill` 增 `origin: TradeOrigin = SYSTEM_SUGGESTED` 形参,合成 Trade 时盖戳;`ExecutionReportApplier` 不传(默认 system),`ManualTradeApplier` 传 `USER_DISCRETIONARY`。
- **三分流读取面**:绩效 API 按 origin 聚合 + 暴露三桶 split;**实盘就绪度 / KPI 头部只读 `system_suggested` 桶**(用户 alpha 永不计入系统能力证据,codex P0-7)。
- **前向约束**:acceptance 策略 3 门 / 自进化评分当前用 0.0 占位(未接真实成交);**未来接真实成交数据时,必须按 `origin=system_suggested` 过滤**(`Trade.origin` 已就位以支撑)。本约束记此,接线任务须遵守。
