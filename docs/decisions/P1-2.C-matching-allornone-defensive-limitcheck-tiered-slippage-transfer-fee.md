## 决策摘要

QuantMind 第一阶段 MockBroker 撮合增强与成本细化采用 **ALL_OR_NONE 撮合 + 防御性涨跌停 re-check + 滑点流动性分级 + 深市过户费引入 + cost_calculator 抽出 + MarketMetaProvider 注入** 架构,完成 P1-2 三子阶段全锁的最后一块拼图,与 P0-4 状态机 + P0-7 14-check + P1-2.A 持久化 + P1-2.B MTM 协同生效:

1. **ALL_OR_NONE 撮合(第一阶段不模拟 partial fill)**:`MockBroker._fill_order` 严守"`filled_volume = order.volume`(全成)或 `filled_volume = 0`(REJECTED)"二态;P0-4 状态机 `PARTIALLY_FILLED` 仅由用户回报路径(ExecutionReportApplier)创建,MockBroker 永不写;理由:13 codes 高流动性 + 单笔 ≤5 万元 + 冷却 60min 真实部分成交概率极低;order book depth 模拟是 P2 级工作量(留 amendment);第一阶段保持简单可预测的撮合行为,避免引入 ADV 估算/盘口仿真的长尾 bug。

2. **涨跌停防御性 re-check + REJECTED**:`_fill_order` 在装配 Trade 前必须经 `MarketMetaProvider.get_prev_close(code, today) + get_current_price(code)` 二次读;`fill_price`(包含滑点后的实际成交价)若 ≥ `prev_close × (1 + price_limit_pct(board))`(BUY)或 ≤ `prev_close × (1 - price_limit_pct(board))`(SELL)即 REJECTED with `reason='price_limit_violation_at_fill'`(与 RiskEngine pre-route 失败的 `reason='limit_up_block'`/`reason='limit_down_block'` 不同便于 audit 区分两层拦截点);board → price_limit_pct 走 `backend.data.stock_metadata.get_price_limit_pct(board)` 单一真相源(继承 P0-7 §1.4.2);`mock_broker.py:35` 孤儿 `get_price_limits` 助手实施期 D-007 删除。

3. **滑点流动性分级 1.5 / 1.5 / 3.5 / 1.5 bp**:`config/broker.yaml.slippage_bps_by_board: {sh_main: 1.5, sz_main: 1.5, chuangye: 3.5, etf: 1.5}` 字典写入;`BrokerConfig.slippage_bps_by_board: dict[str, float]` 字段;移除 `models.py:145` 默认 `slippage_bps: int = 2` 标量常量;`_fill_order` 经 `stock_metadata.classify_board(code)` 拿 board → dict lookup;board 不在 dict 即 BrokerConfig validation error(fail-closed,继承 P0-7 §1.5 14-check check 11 缺 stock_meta REJECTED 模式);runtime 不可改 + hot-reload 禁用(继承 P0-7 §2 红线 14);理由:贴近真实 bid-ask spread(沪深主板高流动性 ~1-2 bp / 创业板宽 ~3-5 bp / 宽基 ETF 高流动性 ~1-2 bp),让模拟 PnL 不被滑点系统性低估或高估。

4. **深市过户费 0.00341% 双边引入(现行实际费率)**:`config/broker.yaml.transfer_fee_rate: 0.0000341` 写入;BUY + SELL 双边均收(成交金额 × 0.0000341);**采用现行实际费率 0.00341% 而非用户初拟 0.01%**(沪深两市自 2022-04-29 起统一为成交金额双边 0.00341% / 三厘四,公开报告:中国结算《关于调整沪深 A 股交易过户费收费标准的通知》);Trade schema 扩展 `transfer_fee: float = Field(ge=0.0)` 字段(非破坏式扩展,无需 P0-3 amendment);理由:不引入会让模拟 PnL 系统性偏乐观(虽 0.00341% 单笔影响小,45 交易日累计 + 5 单/日 ≈ 225 笔 BUY+SELL 双边累计影响不可忽略 vs P0-6 累计 PnL ≥0 硬门槛)。

#### 1.1.1 _fill_order 二态决策树

```python
# backend/broker/mock_broker.py(P1-2.C 重写)

async def _fill_order(self, order: Order, now: datetime) -> OrderResult:
    """ALL_OR_NONE 撮合 + 涨跌停防御性 re-check + 流动性分级滑点 + 完整成本计算。

    第一阶段不模拟部分成交。两态:
      filled_volume == order.volume → OrderResult.FILLED + Trade 入账
      filled_volume == 0            → OrderResult.REJECTED + reason 透明
    禁止 0 < filled_volume < order.volume 的中间态。
    """
    # 1. 板块识别(单一真相源,继承 P0-7 §1.4.2)
    board = self._stock_metadata.classify_board(order.code)
    if board is None:
        return self._reject(order, reason="unclassifiable_board_at_fill", now=now)

    # 2. 涨跌停防御性 re-check(MarketMetaProvider 注入,继承 §1.2)
    prev_close = await self._market_meta.get_prev_close(order.code, today_in_shanghai().strftime("%Y-%m-%d"))
    current_price = await self._market_meta.get_current_price(order.code)
    if prev_close is None or current_price is None:
        return self._reject(order, reason=f"market_meta_unavailable_at_fill:{order.code}", now=now)

    limit_pct = self._stock_metadata.get_price_limit_pct(board)  # P0-7 §1.4.2 单一真相源
    upper_limit = round(prev_close * (1 + limit_pct), 2)
    lower_limit = round(prev_close * (1 - limit_pct), 2)

    # 3. 计算 fill_price(含 board 分级滑点,继承 §1.3)
    slippage_bps = self._broker_cfg.slippage_bps_by_board.get(board.value)
    if slippage_bps is None:
        return self._reject(order, reason=f"slippage_bps_missing_for_board:{board.value}", now=now)

    fill_price = self._apply_slippage(order, slippage_bps_for_this_order=slippage_bps)

    # 4. 涨跌停违规判定(BUY ≥ upper / SELL ≤ lower 即 REJECTED)
    if order.direction == OrderDirection.BUY and fill_price >= upper_limit:
        return self._reject(order, reason="price_limit_violation_at_fill", now=now)
    if order.direction == OrderDirection.SELL and fill_price <= lower_limit:
        return self._reject(order, reason="price_limit_violation_at_fill", now=now)

    # 5. 完整成本计算(独立模块,继承 §1.4)
    cost = calculate_cost(
        order=order,
        board=board,
        fill_price=fill_price,
        broker_cfg=self._broker_cfg,
    )

    # 6. 装配 Trade(全成)
    trade = Trade(
        trade_id=self._gen_trade_id(),
        order_id=order.order_id,
        code=order.code,
        price=fill_price,
        volume=order.volume,
        amount=order.volume * fill_price,
        direction=order.direction,
        commission=cost.commission,
        stamp_tax=cost.stamp_tax,
        slippage_cost=cost.slippage_cost,
        transfer_fee=cost.transfer_fee,           # P1-2.C 新增
        net_amount=self._compute_net_amount(order, fill_price, cost),
        traded_at=now,
    )
    # ... 后续 cash / positions / order.filled_volume 更新(P1-2.A applier 路径) ...

    return OrderResult(status=OrderStatus.FILLED, trade=trade)


def _reject(self, order: Order, reason: str, now: datetime) -> OrderResult:
    """统一拒绝路径。filled_volume = 0;触发 P0-4 状态机 DISPATCHED → REJECTED 合法迁移。"""
    log.warning("order_rejected_at_fill", order_id=order.order_id, reason=reason)
    return OrderResult(
        status=OrderStatus.REJECTED,
        trade=None,
        rejection_reason=reason,
        rejected_at=now,
    )
```

```python
            "chuangye": 3.5,
            "etf": 1.5,
        },
    )

    @field_validator("slippage_bps_by_board")
    @classmethod
    def _validate_slippage_dict(cls, v: dict[str, float]) -> dict[str, float]:

        for board, bps in v.items():
            if bps < 0 or bps > 50:
                raise ValueError(f"slippage_bps for board {board} = {bps} out of [0, 50]")
        return v

    # P1-2.C 删除:slippage_bps: int = 2(替换为 slippage_bps_by_board)
```

```python
# backend/broker/mock_broker.py(改造)

def _apply_slippage(self, order: Order, slippage_bps_for_this_order: float) -> float:
    """根据 board 分级 bps 计算 fill_price。

    Args:
      order: 含 direction(BUY/SELL)和 price(限价)
      slippage_bps_for_this_order: 由 _fill_order 经 board lookup 取出
    """
    if slippage_bps_for_this_order < 0 or slippage_bps_for_this_order > 50:
        # fail-closed,虽 BrokerConfig validator 已守一道,这里再守
        raise ValueError(f"invalid slippage_bps: {slippage_bps_for_this_order}")

    bps_decimal = slippage_bps_for_this_order / 10000  # 1.5 bps → 0.00015

    if order.direction == OrderDirection.BUY:
        return round(order.price * (1 + bps_decimal), 2)
    elif order.direction == OrderDirection.SELL:
        return round(order.price * (1 - bps_decimal), 2)
    else:
        raise ValueError(f"unsupported direction: {order.direction}")
```

```python
@dataclass(frozen=True)
class OrderCostBreakdown:
    """单笔订单完整成本拆解。frozen — 就地 mutation 红线违规。

    所有字段单位:元(CNY)。total_cost = commission + stamp_tax + slippage_cost + transfer_fee。
    """

    slippage_cost: float    # ≥ 0;|fill_price - order.price| × volume(等价 board 分级 bps × amount)
    transfer_fee: float     # ≥ 0;BUY+SELL 双边按 broker_cfg.transfer_fee_rate(0.00341% 双边)
    total_cost: float       # = commission + stamp_tax + slippage_cost + transfer_fee
```

#### 1.4.2 calculate_cost 纯函数

```python
def calculate_cost(
    order: Order,
    board: Board,
    fill_price: float,
    broker_cfg: BrokerConfig,
) -> OrderCostBreakdown:
    """纯函数 — 无 self / 无 IO / 无副作用。

    Args:
      order: 订单(含 direction, volume, price 等)
      board: 已分类的板块(由 _fill_order 经 stock_metadata.classify_board 取得)
      fill_price: 含滑点的实际成交价(由 _fill_order 经 _apply_slippage 取得)
      broker_cfg: BrokerConfig(commission_rate / stamp_tax_rate / transfer_fee_rate / slippage_bps_by_board / min_commission)

    Returns:
      OrderCostBreakdown — 4 个 cost 字段 + total_cost 等式校验

    Raises:
      ValueError: order.volume ≤ 0 / fill_price ≤ 0 / broker_cfg 字段越界
    """
    if order.volume <= 0 or fill_price <= 0:
        raise ValueError(f"invalid order: volume={order.volume}, fill_price={fill_price}")

    amount = order.volume * fill_price  # 成交金额(元)

    # 1. commission(BUY+SELL 双边;min_commission 兜底)
    raw_commission = amount * broker_cfg.commission_rate
    commission = max(raw_commission, broker_cfg.min_commission)

    # 2. stamp_tax(仅 SELL)
    stamp_tax = amount * broker_cfg.stamp_tax_rate if order.direction == OrderDirection.SELL else 0.0

    # 3. slippage_cost
    slippage_bps = broker_cfg.slippage_bps_by_board[board.value]  # KeyError → BrokerConfig validator 已守
    slippage_cost = abs(fill_price - order.price) * order.volume
    # 等价:amount × (slippage_bps / 10000) — 但用 abs(fill_price - order.price) × volume 更直接

    # 4. transfer_fee(BUY+SELL 双边;P1-2.C 新增,采用现行实际费率 0.00341% 双边)
    transfer_fee = amount * broker_cfg.transfer_fee_rate

    # 5. total
    total_cost = commission + stamp_tax + slippage_cost + transfer_fee

    return OrderCostBreakdown(
        commission=round(commission, 2),
        stamp_tax=round(stamp_tax, 2),
        slippage_cost=round(slippage_cost, 2),
        transfer_fee=round(transfer_fee, 2),
        total_cost=round(total_cost, 2),
    )
```

```python
def _compute_net_amount(self, order: Order, fill_price: float, cost: OrderCostBreakdown) -> float:
    """净金额 = 收支 - 全部成本。

    BUY:net_amount = -(amount + commission + slippage_cost + transfer_fee)(stamp_tax 仅卖)
    SELL:net_amount = +(amount - commission - stamp_tax - slippage_cost - transfer_fee)
    """
    amount = order.volume * fill_price
    if order.direction == OrderDirection.BUY:
        return -(amount + cost.commission + cost.slippage_cost + cost.transfer_fee)
    elif order.direction == OrderDirection.SELL:
        return amount - cost.commission - cost.stamp_tax - cost.slippage_cost - cost.transfer_fee
    else:
        raise ValueError(f"unsupported direction: {order.direction}")
```

```python
class WatchlistMarketMetaProvider:
    """MarketMetaProvider 第一阶段实现:adata/akshare 日线 + watchlist_market_snapshots。"""

    def __init__(
        self,
        market_data: MarketDataService,         # adata 主 + akshare 备(P0-8 §1.1)
        snapshot_repo: WatchlistSnapshotRepo,   # P0-8 watchlist_market_snapshots 30s
        holidays: HolidaysService,              # 上一交易日推算
    ):
        self._market_data = market_data
        self._snapshot_repo = snapshot_repo
        self._holidays = holidays

    async def get_prev_close(self, code: str, trade_date: str) -> float | None:
        """读上一交易日收盘价。

        实现:trade_date 上一交易日 → adata.get_daily_history(code, prev_trade_date, prev_trade_date).close
        adata 失败时回退 akshare;两源都失败返 None。
        """
        prev_trade_date = self._holidays.previous_trading_day(trade_date)
        try:
            df = await self._market_data.get_daily_history(code, prev_trade_date, prev_trade_date, source="adata")
            if df is not None and not df.empty:
                return float(df.iloc[0]["close"])
        except Exception:
            pass
        try:
            df = await self._market_data.get_daily_history(code, prev_trade_date, prev_trade_date, source="akshare")
            if df is not None and not df.empty:
                return float(df.iloc[0]["close"])
        except Exception:
            pass
        return None  # fail-closed

    async def get_current_price(self, code: str) -> float | None:
        """从 watchlist_market_snapshots 读 30s 最新价。

        实现:Redis ≤60s → Mongo ≤300s 二级回退(继承 P1-2.B §1.1.3 三级回退前两级;
        last_known_cached 不引入 — P1-2.C 涨跌停判定要求实时性,陈旧价格判定不可信)。
        """
        snap = await self._snapshot_repo.get_latest_redis(code, max_age_seconds=60)
        if snap is not None:
            return snap.close_price
        snap = await self._snapshot_repo.get_latest_mongo(code, max_age_seconds=300)
        if snap is not None:
            return snap.close_price
        return None  # fail-closed(不回退 last_known_cached)
```

### 4.3 现行实际过户费率核实(2026-05-10)

- **2022-04-29 起**沪深两市 A 股交易过户费统一调整为 **按成交金额双边收取 0.00341%**(三厘四);来源:中国证券登记结算有限责任公司《关于调整沪深 A 股交易过户费收费标准的通知》(2022)
- 本决策采用现行实际费率 **0.00341% 双边**(=0.0000341);用户初拟的 **0.01% 双边**约为现行 3 倍,会让模拟成本系统性偏高 0.0068% / 完整买卖回合 → 45 交易日 × 5 单/日 × 平均 5 万元 ≈ 11.25 万元周转 × 0.0068% 偏差 ≈ 7.65 元偏差(累计可观;不可忽略)
- 若未来监管调整费率,经 `P1-2.C-amendment-{date}-transfer-fee-rate.md` 走 amendment(yaml diff + 重启)

### 4.5 为什么第一阶段不模拟 partial fill

- 13 codes 全是高流动性大盘(沪深主板 + 宽基 ETF);单笔 ≤5 万元 / 单股 ≤15% 持仓上限;真实部分成交概率极低
- order book depth 仿真需要引入 ADV 估算 + 多档报价 + 队列延迟模型,长尾 bug 风险高;P2 级工作量
- P0-4 状态机已支持 PARTIALLY_FILLED(经用户飞书回报路径);MockBroker 在 simulation_auto 模式不模拟 partial 不会让 feishu_interactive 模式失能(用户回报路径独立)
- P0-6 验收硬门槛(指令完整率 ≥95%)在 ALL_OR_NONE + 严格 universe + 流动性分级滑点下应可达成;若实施期发现需要 partial,通过 amendment 升级

### 4.6 为什么涨跌停 MockBroker 防御性 re-check

- 双层守门 vs 三层守门:P0-7 已锁 InstructionPlanBuilder 五道早返 + RiskEngine 14-check 双层;MockBroker re-check 是第三层 defense-in-depth
- 真实券商 OMS 在 fill 时也会再次校验涨跌停(限价单不会撮合越界);模拟必须模仿同语义
- pre-route 与 at-fill 时间差:current_price 在两层之间可能跳动(尤其涨停板边缘);仅靠 pre-route 失去时变性
- 两层 reason 不同(`limit_up_block` vs `price_limit_violation_at_fill`)便于 audit 区分两层拦截点
- mock_broker.py:35 助手早已存在但未连入是历史遗留;实施期 D-007 顺带清理(单一真相源)

### 4.7 为什么滑点流动性分级而非固定 2bp

- 真实 bid-ask spread:沪深主板高流动性 ~1-2 bp / 宽基 ETF ~1-2 bp / 创业板宽 ~3-5 bp(2024-2025 公开行情数据)
- 固定 2 bp 让所有 board 一刀切:主板被高估 + 创业板被低估;模拟 PnL 在不同 board 下会出现系统性偏差,影响 P0-6 累计 PnL ≥0 与最大回撤 ≤8% 验证准确性
- 1.5 / 3.5 区分既不过于激进也不过于保守:贴近实际同时与 P0-6 验收门槛对齐(stamp_tax + commission + transfer_fee + 1.5-3.5 bps slippage 总成本 < 0.15% 单边,与 ≤8% 最大回撤约束相容)
- 配置走 yaml 而非代码常量:运维可见性 + amendment 流程清晰

### 4.8 为什么 BrokerConfig + Trade strict 升级

- P0-3 §2 红线 12 锁定 frozen Pydantic v2 strict + extra="forbid" 三层守门(strict 类型转换严格 / forbid 拒绝额外字段 / frozen 不可变)
- 当前 BrokerConfig + Trade 仅 frozen=True,缺 strict + extra="forbid" 两层
- yaml 多余字段静默忽略历史 bug(extra=allow 默认行为)— strict 升级后 ValidationError 早暴露
- 新增 transfer_fee 字段时顺带升级,minimal cost 收益最大
