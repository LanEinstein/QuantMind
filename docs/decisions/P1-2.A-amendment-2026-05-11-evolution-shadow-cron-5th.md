## 触发原因

P2-2 自进化机制边界 dedicated session 锁定后,用户 Round 2 Q1 选 "BrokerScheduler 独立第五 cron"(evolution_shadow_run 22:00 mon-fri Asia/Shanghai)。理由:

- 复用已锁定的 P1-2.A BrokerScheduler 单实例 APScheduler(避免新起 EvolutionScheduler 进程的运维复杂度)

- 与现 4 cron(eod_pipeline 16:00 / mirofish_postclose 17:00 / advance_day 09:00 / intraday_mtm 30s)时间错峰不冲突
- 触发 P2-2 §1.3 shadow validate + §1.6 飞书主动通知主链路

# backend/scheduler/broker_scheduler.py(本 amendment 后状态)
class BrokerScheduler:
    """单实例 APScheduler;3 + 1 + 1 = 5 cron jobs。"""

    def __init__(self, ...):

        self._register_evolution_shadow_run()     # cron 5: 22:00:00 mon-fri ★ 新增

    def _register_evolution_shadow_run(self) -> None:
        """注册 P2-2 自进化 shadow validate cron(22:00 mon-fri Asia/Shanghai)。

        - 写 audit shadow_evolution_run_completed

        - 单实例(继承 P1-2.A 单实例 BrokerScheduler;严禁并行)
        - 失败处理 = 1 次重试 + log + audit + 不发飞书 + 不阻断 production simulation_auto

        self._scheduler.add_job(
            self._run_evolution_shadow_run,
            trigger=CronTrigger(
                hour=22,
                minute=0,
                second=0,
                day_of_week="mon-fri",
                timezone=ZoneInfo("Asia/Shanghai"),

            id="evolution_shadow_run",
            replace_existing=True,
            max_instances=1,  # 严禁并行(继承 P1-2.A 单实例 BrokerScheduler)
            misfire_grace_time=300,  # 5 min 容忍延迟启动;超出仍执行
        )

    async def _run_evolution_shadow_run(self) -> None:
        """evolution_shadow_run cron 入口函数。"""
        from backend.services.evolution_dispatcher import EvolutionDispatcher
        # 严禁 import backend.{api, broker, risk, llm, agents, mirofish, data}
        # 继承 P2-2 §2 红线 17 自进化模块依赖隔离

        dispatcher = EvolutionDispatcher(...)
        try:
            await dispatcher.run_pending()
        except Exception as e:
            logger.error("evolution_shadow_run failed: %s", e, exc_info=True)
            await self._audit_store.write(
                event_type=AuditEventType.SHADOW_EVOLUTION_RUN_COMPLETED,
                actor=AuditActor.SCHEDULER,
                outcome=AuditOutcome.FAILURE,
                payload={"error": str(e), "error_kind": type(e).__name__},
                reason_namespace="self_evolution_lifecycle",
                resource_type="self_evolution_artifact",
            )

            # 不阻断 production simulation_auto

### P1-2.A §1.6 EOD chain 失败处理(同步说明)

**原 EOD chain 失败处理**(P1-2.A §1.6):

```
EOD chain 核心路径(execution_cutoff → chase_poller → acceptance_report → snapshot)任一失败:
  1 次重试 → 仍失败 → alert 入运维 + 冻结次日买卖类 InstructionPlan 路由(第五种冻结来源 eod_pipeline_freeze)
```

**本 amendment 后 evolution_shadow_run 失败处理(不同;较 EOD chain 宽松)**:

```
evolution_shadow_run 失败:
  1 次重试 → 仍失败 → audit shadow_evolution_run_completed outcome=FAILURE + log
  + 不发飞书(避免误通知)
  + 不冻结买卖类路由(非生产路径)
  + 不阻断 production simulation_auto(自进化是辅助而非核心)
  + pending artifact 仍在 pending 状态;次日 22:00 重试
```

理由:evolution_shadow_run 失败比 EOD chain 失败影响小;EOD chain 是 production 关键路径,evolution_shadow_run 是辅助路径。
