# 证据层完整性核查记录（2026-08-20）

> 本轮在为战法卡片核对引用时做的一次性全量核查，只报告事实与处置建议，不改动任何既有工件。

## 一、做了什么

把全部 observation 的 `evidence[].transcript_span.raw_text` 与对应 transcript 的 `sentences[start:end+1]` 拼接结果逐条比对。

- 检查的证据 span：**2790** 条
- 不匹配：**43** 条，落在 **10** 个 aweme_id 上
- 其中 40 条只是标点/断句差异，3 条有词面差异（多/少一个词）

## 二、结论：不是数据损坏，是版本文件选择问题

observation 目录里共 **1135 个文件 / 1111 个唯一 aweme_id**，差额来自 schema 升级留下的并存版本：

```
7552015322325699840.json          ← v1（旧）
7552015322325699840-v1.1.json     ← v1.1（新）
7669063381873462208-v1.2.json     ← 个别有 v1.2
```

抽样验证（`7552015322325699840`）：**v1 文件的 5 条 raw_text 全部与 transcript 不符，v1.1 文件的 5 条全部相符**。全部 43 条不匹配都落在有更高版本后继文件的 aweme_id 上。

也就是说：**旧版文件的 raw_text 已被新版修正，旧文件只是没有删除。**

## 三、处置

**不修改任何文件。** 改动旧版 raw_text 既无必要（新版已正确），也会破坏 append-only 与版本留痕。改为确立一条引用纪律：

> **引用 observation 时一律取该 aweme_id 的最高版本文件**（`-v1.2` > `-v1.1` > 无后缀）。任何按 `observations/*.json` 通配读取的脚本，都要先按 aweme_id 归并、取最高版本，否则会同时读到新旧两份并可能取到已被修正的旧文本。

受影响的 10 个 aweme_id（引用时须取高版本）：

`7526939325557165347`、`7552015322325699840`、`7562170397225258280`、`7566602982977376372`、`7602233626348496192`、`7626700051746734178`、`7647445389893913039`、`7658346105893142863`、`7660119917865709391`、`7669063381873462208`

## 四、对本轮产出的影响

本轮三份新文档（第一批确认稿、Base v3、第二批卡片）里的每一条原话都**直接对照 transcript 的 `sentences` 拼接结果验证过**，不依赖 observation 的 raw_text，因此不受此问题影响。核查中发现并已修正的引用误差共 4 处（本轮自身笔误，均为标点/断句），修正后全部与 transcript 逐字一致。

## 五、给后续工作的两条提示

1. `scripts/yeren_research/evidence_quote.py` 对旧版文件会抛 `evidence raw_text does not match transcript sentences`——这是**正确行为**，说明该文件已被更高版本取代，应改用高版本文件，而不是放宽校验。
2. 统计类脚本（obs 计数、覆盖率）若直接数文件数会得到 1135 而非 1111。既有账本里的「obs 1112／唯一 1088」正是同一现象，不是漏处理。
