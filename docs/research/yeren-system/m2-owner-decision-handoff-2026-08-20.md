# M2 Owner 决策接手说明（2026-08-20）

## 给下一 session 的任务

请先完整阅读本仓库的 `AGENTS.md`、`docs/research/yeren-system/m2-playbook-cards-luna-execution-plan-2026-08-20.md`，再结合本说明、增量 Casebook、Base v2 草案、战法卡草案以及其中引用的 observation/hypothesis，独立分析下面的未决问题。

你的职责是：

1. 综合全部已有证据，给出每个问题的建议判断；
2. 对每个判断说明支持证据、反证或歧义、以及如果采纳会怎样影响后续系统设计；
3. 清楚区分“语料直接证明的事实”“基于多条证据的推断”“需要 owner 选择的设计决策”；
4. 最后给出一份便于 owner 决策的总表，但不要替 owner 做最终决定。

本轮只需要分析和提出理由，不要修改代码、不要推进 M3、不要做回测或命中率统计，也不要把任何内容写成真实交易下单逻辑。系统永远只维护模拟盘。

## 当前工作背景

原计划预计新增 18 条语料，但资产审计发现旧 observation 共有 1088 条，当前 metadata 共有 1111 条，实际差集为 23 条（固定序号 1089—1111）。这 23 条都已有 transcript、ledger `done` 和 observation，并通过 schema validation。本轮没有新增官方事件，也没有真实券商订单。

新增语料把 8 月 13—19 日的连续证据补完整了：

- 作者曾说“不到 4000 点不走”，但 3994 点时没有按原口径离场；
- 随后作者承认不该建议锁仓到 4000，并对部分事件退出建议道歉；
- 之后作者自述减仓到三成、提取资金，并强调风险大于机会时要控制仓位；
- 这些仍是视频口播，不是账户成交回单，因此可以确认“原触发器未按口头计划执行并被撤回”的证据链，但不能确认具体账户、证券、数量和成交结果；
- 语料反复出现“符合预期继续持有、不符合预期退出、超预期增加暴露”的三路结构，但阈值、仓位幅度和反馈窗口没有冻结；
- 语料中的“全军出击、半仓、三成”等数字来自不同时间或可能不同账户，缺少分母和回单，不能直接变成系统参数；
- 8 月 19 日的“520 战法”包含 5/20/30 日线和止跌语言，但作者明确把它称为短线套利、挣一口就走，因此暂不并入首批右侧波段卡；
- 8 月 20 日另有一条极低信息量 ASR，不产生交易证据。

因此，当前 Base 的核心边界是：先复刻作者的行为语义和动作关系，不把口播、比例、阈值、证券池或事后解释伪装成已验证的生产规则。

## 一、总体仓位行为框架：请逐项判断

当前草案使用五个行为词描述仓位变化：空仓、试错、加仓、锁仓、推仓。它们暂时被当作研究语言，不是自动运行的生产状态机。

1. 是否应该接受这五个词只作为行为语言？如果不接受，请说明应如何改写，才能既忠实于语料又不提前制造确定性状态机。
2. 是否应该把“锁仓”拆成两种：一种是作者主动决定继续持有，另一种是因为亏损、犹豫或触发器失效而被迫套住？请结合 4000 点证据判断这个区分是否必要。
3. 是否应该把“推仓”只保留为风险极值或反例记录，而不作为目标系统鼓励的正向状态？请说明“全军出击”等语料是否足以支持相反结论。
4. 是否应该暂不冻结任何仓位百分比，只确认“符合/不符合/超预期”对应的动作关系？请判断三成、半仓、全军出击等口径是否有足够证据成为 Base 参数。

## 二、六张战法卡：请逐项判断

### 卡 1：右侧波段入场

草案将语义概括为“候选 → 激活 → 回踩 → 介入”。旧语料出现趋势向上、量价、5 日线上穿 20 日线、20/30 日线拐头等描述；新增 1110 的 520 也使用均线和止跌语言，但被作者限定为短线套利。

请判断：是否认可“候选—激活—回踩”作为 Base 语义，同时把具体均线、天数、失效阈值留到后续验证？请特别说明 520 套利是否应完全与波段卡分开。

### 卡 2：分歧切核心 / 弱势抱团

草案把它限定为短线题材层的分歧处理和去弱留强，不把它扩展到机构主导的中长线波段仓。新增语料继续支持“龙头/中军相对强、后排相对弱”的观察，但没有固定证券池和量化阈值。

请判断：是否应保留这张卡，并明确它只处理短线题材内部的相对强弱？如果应并入其他卡，请说明并入“修复轮动”还是“防守退出”更合理。

### 卡 3：红卖绿买修复轮动

草案把它作为独立候选卡：修复较强者兑现或退出，弱者不因单日反弹自动转强；也可以把它并入分层退出/去弱留强。新增语料同时出现弱修复、强修复和修复后退出的相反场景。

请判断：证据是否足以支持独立成卡？如果不足，应该保留为哪张卡的子规则？请说明“红卖绿买”是稳定行为原则，还是只在特定修复阶段成立的特殊手法。

### 卡 4：禁亏损补仓 + 被套反弹减半

草案把“下跌不能补、亏损不摊平”列为最稳定的核心语义，把“反弹时减半/减仓”只保留为方向，不冻结比例。新增语料重复支持“不符合预期才退出、下跌不能补、反弹是离场机会”。

请判断：是否确认“禁亏损补仓”是 Base 的第一条核心原则？是否同意暂时只确认反弹减仓方向，而不确认“一半”等比例？请指出是否存在足以推翻这条核心原则的反证。

### 卡 5：事前锁定退出触发器

草案保留“入场前绑定退出条件”的结构语义，但把“锁仓两天、4000 点”等具体时间和点位留作样本，不当作参数。新增 1106—1109 证明作者曾未按 4000 点口径执行，后来撤回原建议并声称减仓。

请判断：是否仍认可事前锁定退出触发器作为 Base 语义？如果认可，请说明应如何把“事前规则”“作者口头承认未执行”“后续自述减仓”“真实成交回单”四层信息分开，避免把失败执行写成成功执行。

### 卡 6：混沌—退潮—恐慌盘防守链

草案将其作为组合防守卡：行情混沌或短线退潮时控制仓位，等待情绪/恐慌盘释放和修复，不自动推导为全仓清空。它与卡 2 的区别是：卡 2 选择短线相对强者，卡 6 管理组合风险暴露。

请判断：是否接受这张防守卡及其与卡 2 的职责分离？如果不接受，请说明应把“短线退潮、等待恐慌盘、修复减仓、保持部分防守仓”如何重新组织。

## 三、请使用的判断格式

请对总体问题和六张卡分别给出：

- 建议：接受 / 修改后接受 / 暂缓 / 否决；
- 直接证据：引用 observation、原话或证据链，不只复述草案；
- 反证与歧义：指出哪些地方不能过度推断；
- 对系统的影响：会冻结什么、明确不冻结什么、下一阶段应验证什么；
- 给 owner 的决策建议：用通俗语言说明为什么这样选。

最后请给出一个“如果 owner 现在只做最少确认，优先确认哪几项”的排序。最终选择权属于 owner，不要把模型建议写成已经批准的系统规则。
