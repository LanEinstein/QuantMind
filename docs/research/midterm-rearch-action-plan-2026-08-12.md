# QuantMind 中长线重构行动计划书

日期:2026-08-12(v2,按 owner 四点反馈修订) · 状态:待 owner 审批 · 执笔:Claude(Sonnet 5)

## 一、重构的性质:推倒重来,择优借鉴

这次不是在旧体系上打补丁,而是完全重构。之前积累的那套冻结原则、红线条文、amendment 流程,统统作废,不再构成约束;唯一保留的底线是永禁真实券商下单——系统只维护模拟盘,真实操作永远由你本人在券商 App 里完成。

作废不等于清零。有几样旧资产质量很高,直接拿来用,避免重复造轮子:约 29 GB 的 Tushare 全市场 PIT 数据档和摄取管线;回测与统计检验的现成代码;Vue 前端骨架和飞书收发通道的代码;模拟盘账本。其余的(多 Agent 辩论链、14 项风控检查、对账 ticket、验收框架等短线时代的复杂机构)一律封存归档,新系统用不上就不背着。

新体系只做四件事:中长线投资;以「全能的野人」的交易体系为蓝本建战法池;Tushare 数据验证与信号生成;飞书作为行动通道、前端作为查看通道。

## 二、工程风格约定:反过度防御

这条写在所有技术章节前面,对本次重构全程有效,对 Claude 和 codex 同样有效。参考 [HERO-Anti-OverDefense](https://github.com/wanshuiyin/HERO-Anti-OverDefense),四种行为明令禁止:没有实际用途的校验和与指纹;为本项目根本不会出现的输入写防御;用评分表和机械复验循环替代人的判断;为想象中的未来需求预建功能开关、迁移框架、兼容层。

判断标准就用 HERO 那句话:"这能检测到什么具体故障,我会因此做出什么不同的决定?"答不上来就不写。发现问题可以随时报告(搜索不受限),但动手修只修主线范围内的东西(修复受限)。codex review 同理:主线之外的 findings 记下来就行,不阻塞进度。

## 三、语料流水线:逐条处理,恒定磁盘占用

目标不变:把「全能的野人」(抖音号 203775400)的 1086 条作品变成带发布时间戳的文字库。已核实内容形态以每日收盘后的「X月X日复盘」口播为主,所以文字信息的主体在语音里,必须做转写;发布时间精确到秒,是对照分析的关键字段。

处理方式按你的要求改为流式:从最早的视频开始,每次只处理一条——下载、本地转写、落文本和元数据、删除视频文件、进下一条。磁盘上任何时刻只有一条视频,占用恒定在几百 MB 以内;从最早开始也让语料天然按时间序生长,方便边采边做对照分析。进度记在一个处理台账里(视频 ID → 已完成),断点续跑、幂等重入,跑挂了从断点继续,不重复下载。

每条视频最终留下的东西:转写全文(带句级时间偏移)、标题、描述、话题标签、发布时间戳、互动数据、转写模型版本。原始视频不留档。选做项是在删除前抽几张关键帧(他的视频常有「空仓 试错 加仓 锁仓 推仓」这类大字贴片),给转写文本补充结构信息,单条只增加几百 KB。

下载工具优先用现成开源:[TikTokDownloader](https://github.com/JoeanAmier/TikTokDownloader) 或 [Douyin_TikTok_Download_API](https://github.com/Evil0ctal/Douyin_TikTok_Download_API),配合你浏览器已登录的 cookie;开源工具失效就退回用你的 Chrome 半自动翻页,慢但稳。转写选阿里开源的 [FunASR](https://github.com/modelscope/FunASR)(Paraformer 中文模型,财经口语识别好于 Whisper 系),全程离线本地跑。

## 四、战法池:提炼、验证、固化

语料齐了以后分三步。

第一步提炼。用 LLM 对全量转写做归纳,产出他的总体交易框架和一张张战法卡片。从主页已能看出框架雏形:他反复讲「空仓、试错、加仓、锁仓、推仓」这套仓位状态语言,底层是一个清晰的仓位状态机,正好固化成工作流。每张卡片写明名称、适用市况、入场条件、加减仓与退出规则、仓位约束,附原话引用和视频出处,由你逐张过目确认,防止曲解。

第二步验证。他讲的每种战法转成确定性规则后,用 Tushare 数据回测,复用现成的回测与统计检验代码;标准从简:历史上真赚钱、回撤你能接受、不是靠一两次运气。时间戳在这里有独特价值——把他每天复盘的观点按发布时间对齐行情,直接统计他本人历史发言的命中率和假想执行收益,等于先验证"这个人值不值得学",再验证"每一招灵不灵"。防前视只有一条规则:视频发布在收盘后,他的发言只能预测次日及之后的行情。验证不过的战法标记留档,如实报告,不进战法池。

第三步固化。新模块 `backend/playbook/`:每个战法一个 spec,带出处和状态(候选/已验证/未通过),配确定性执行器,盘后按战法池扫描全市场生成建议。

## 五、交互:飞书做行动通道,前端做查看通道

飞书保留,定位收窄为"只在需要你动手时说话"。系统只在四类时刻推送:最初的买入建议、持仓过程中的仓位调整建议、增配建议、减仓乃至清仓建议;其余时间完全静默,没有日报、没有心跳、没有例行汇报。推文具体到个股,采用总分结构:先一句话说清结论(动哪只、怎么动、动多少),再分点讲理由(触发了哪个战法、当前盘面依据、仓位现状);语言通俗、连贯、流畅、自然,像一个靠谱的投资顾问在跟你说话,不堆术语不打官腔。

你在飞书里的回复走 LLM 理解,不再要求任何固定格式。你用自然语言说做了什么("买了五千股,成交价 12.3"、"没买,再看看"、"清了一半"),后台 LLM 理解你的意思,调用 agent 更新模拟盘的持仓和现金状态,然后回一条简短确认,说清系统把账户更新成了什么样;理解不了或信息不全(比如缺成交价)就追问一句。改错了你直接再说一句,系统照改。模拟盘从此就是你真实账户的镜像,所有信号和建议都基于这面镜子生成。

前端负责剩下的一切查看需求,四个页面:战法池管理(卡片、状态、回测成绩、原话溯源)、语料浏览器(按日期翻转写全文、全文检索、跳回原视频)、对照分析(时间轴并排他的发言、我们的信号、真实行情)、账户面板(模拟盘持仓、净值曲线、历史建议与执行记录)。仍然只监听 127.0.0.1,远程走 SSH tunnel。

## 六、节奏

五步走,每步末尾你点头再进下一步。M1 搭流式采集转写管线并开始跑(机器时间为主,1086 条大约几天,期间语料持续生长);M2 战法提炼加你的逐张确认;M3 验证——回测加发言-行情对照,工作量和价值都最大的一步;M4 战法池执行器、飞书建议通道与回复理解链路、前端四页;M5 归档旧治理文档,立一页新的简明章程和任务看板。你批准后 M1 立即开工。

## 七、两个提前说清的风险

一是采集侧:抖音反爬更新勤,开源工具可能阶段性失效,备了浏览器半自动兜底,进度可能放缓但不会卡死。二是内容侧:语料的量没问题,但"他讲的"和"有效的"之间隔着验证这一步;如果对照分析发现他的历史命中率并不显著,这个结论本身也值钱,如实报告,战法池只收验证过的东西。
