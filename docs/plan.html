维护协议

本节是 AI 与人类协作的强制流程。CLAUDE.md 第 4 节"项目进度管理协议"是本表的浓缩复制, 二者必须保持语义一致;若冲突以本表为准。

动作要求失败处理
会话开始 第一件事 grep #session-log 与 status="doing", 写明上次停在哪、下一步做什么。 未先调查就动手 = 违规;退回重做。
认领任务 把任务源码状态从 todo 改为 doing, 同步填写 session_date;若依赖未完成改 blocked + 在 notes 写明 blocked_by。 只改 localStorage 不算项目进度;必须改源码 TASKS。
完成任务 源码状态改 done, 回填 commit(真实 hash 7 位)session_date notes(1-2 句 What+Why);触发"修订记录"追加。 测试未跑或失败不得标 done;commit 留空不得标 done。
会话结束 在 SESSION_LOG 顶部追加一条:date / session / owner / state_in / actions / commit / next;修订记录 同步追加一行。 无 SESSION_LOG 条目的 commit 视为孤儿提交。
改决策边界 必须先新增 docs/decisions/*-amendment-YYYY-MM-DD-*.md。 没有 amendment 的行为差异视为违规实现。
改本文件 同步修改 TASKS 数据、SESSION_LOG 与"修订记录", 保持浏览器渲染和源码一致。 只改 localStorage 不算项目进度。
