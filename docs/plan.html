维护协议

本节是 AI 与人类协作的强制流程。CLAUDE.md 第 4 节"项目进度管理协议"是本表的浓缩复制, 二者必须保持语义一致;若冲突以本表为准。

动作要求失败处理
会话开始 第一件事 grep #session-log 与 status="doing", 写明上次停在哪;**确定本次活动 Phase** = 最早一个含 status="todo" 的字母 Phase, 并列出该 Phase 内 depends 已满足的任务集 — 本次 session 一次性完成该 Phase 所有可做任务, **不再按单子任务粒度切 session**(2026-05-12 用户锁定)。 未先调查就动手 = 违规;只挑一个任务做完就收工 = 违规(除非用户显式要求 single-task 或剩余任务过大需要拆分,且在 SESSION_LOG 说明)。
认领任务 把活动 Phase 内所有可做任务源码状态从 todo 改为 doing, 同步填写 session_date;若依赖未完成改 blocked + 在 notes 写明 blocked_by。 只改 localStorage 不算项目进度;必须改源码 TASKS。
完成任务 每个任务一次独立 feature commit, 状态改 done, 回填真实 7 位 commit hash + session_date + notes(1-2 句 What+Why);docs-only "状态/commit 翻新" 不在每任务后立即跟, 留到 session 结束统一一次。 测试未跑或失败不得标 done;commit 留空不得标 done。
提交前本地门禁 每个 feature commit 前, 全量本地验证全绿(pytest -q --cov=backend --cov-fail-under=70 + pytest -q backend/risk --cov-fail-under=95 + 前端 type-check/vitest + scripts/redline-check.sh + ruff 触动文件); 全绿即可 commit。 Codex review 改手动调用(2026-05-12 用户锁定): Claude 绝不主动跑 /codex-review / codex review --uncommitted / codex exec; 仅当用户显式要求"跑 codex" / "/codex-review" 时才跑, 那时按 codex-review skill 流程跑(默认 1 cycle, 用户可指定 major-feature 5 轮 R1-R5; 输出 docs/reviews/{task-id}-codex-review-summary.md)。 旧"任何 commit 前 codex 至少 1 cycle 强制"协议作废, 见 ~/.claude/projects/-home-ps-papers-QuantMind/memory/feedback_codex_review_manual_invocation.md。 本地门禁红色 commit = 违规; SESSION_LOG actions 说明 codex 是否被用户调用(没有就写 "codex: manual gate, not run this session")。
会话结束 整个 Phase 全部 done 后(或确实无法继续后), 一次性 docs-only commit 在 SESSION_LOG 顶部追加一条覆盖整个 Phase 的条目: session: "#N phase-X full" / actions 枚举每任务及其 commit hash / next 指下个 Phase 第一个可做任务; 修订记录 同步追加一行。不要每个任务都跟一次 docs-only commit。 无 SESSION_LOG 条目的 commit 视为孤儿提交; 中途 docs-only 翻新 = 违反新协议。
改决策边界 必须先新增 docs/decisions/*-amendment-YYYY-MM-DD-*.md。 没有 amendment 的行为差异视为违规实现。
改本文件 同步修改 TASKS 数据、SESSION_LOG 与"修订记录", 保持浏览器渲染和源码一致。 只改 localStorage 不算项目进度。
