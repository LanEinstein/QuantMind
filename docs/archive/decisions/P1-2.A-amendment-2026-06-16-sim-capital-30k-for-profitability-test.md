# P1-2.A-amendment-2026-06-16 — Raise simulation initial capital ¥9k → ¥30k for the auto-trading profitability test

**Status:** accepted (owner, 2026-06-16)
**Parks for the current test phase:** `P1-2.A-amendment-2026-06-14-initial-capital-9k-low-budget` (the ¥9k low-budget intent is not abandoned, only paused for this sim test). Sets a new ¥30k Normal-tier sim value (distinct from the ¥100k of `P1-2.A-amendment-2026-05-25`).
**Scope:** `config/broker.yaml` `mock.initial_capital` only. Simulation (MockBroker) account capital. No red line touched (永禁真实下单 / 单一构造点 / RiskEngine 14-check / 127.0.0.1 / fail-closed all unchanged).

## Context — why

Owner is running the system in **`simulation_auto` (fully automatic, feishu OFF)** to prove *stable profitability* before switching to feishu-interactive real-money (see [[project-sim-auto-profitability-test-2026-06-16]]).

On 2026-06-16 the 09:35 Line-1 cron ran **end-to-end and correctly**, but placed **0 orders**. Event log (`logs/quantmind.jsonl`):

- frame `LINE1-FRAME-20260615` (5526 codes) → screen 5526 → 1971 → 100 candidates
- budget tier `small`, cash ¥9000 → 16 affordable → shortlist 5 (large banks 601398/601988/600919/601328/601939)
- allocation: `deployable ¥2970` (= ¥9000 × `deploy_fraction 0.33`), inverse-vol split → ¥530–724/name
- **all 5** `line1_allocation_skipped` — *"allocation target 0 lots today (inverse-vol under-deploy)"*

**Root cause:** ¥9000 × 0.33 deploy envelope ÷ 5 names ≈ ¥594/name, **below the cost of one 100-share lot** of the selected ~¥6–8 bank stocks (1 lot ≈ ¥600–800). `cash_to_lots` floors to 0; `line1_context_provider.py:500-509` deliberately skips a 0-lot target (never coerces to 1 lot — that would breach the tranche/concentration envelope). This is **correct conservative behavior, not a bug** — but at ¥9k the strategy cannot deploy a diversified lot, so **no trades occur and profitability cannot be measured.**

## Decision

`config/broker.yaml` `mock.initial_capital`: **9000 → 30000**.

At ¥30k: Normal budget tier (≥¥10k), deployable ≈ ¥30000 × 0.33 = **¥9,900**, inverse-vol split ≈ **¥1,980/name** → **2–3 lots** of a ¥6–8 name → real, diversified, lot-affordable trading → profitability becomes measurable. (Owner chose ¥30k over ¥100k — a smaller, more realistic test float that still clears the per-lot floor.)

This is **simulation test capital**. The eventual feishu real-money account capital is a **separate future decision** (the ¥9k "low-budget" intent is parked, not abandoned; if the real account is genuinely ~¥9k, the small-account 0-lot interaction below must be revisited before that go-live).

## How to apply (account lifecycle — owner-gated)

`recover_state` seeds from `broker.yaml` **only on a fresh deploy with no snapshot**; both plain restart and `ModeRouter` mode-switch **carry forward the existing account's `initial_capital`** (`mode_router.py:330-344`), so a bare edit + restart keeps ¥9000. Applying ¥30k requires re-baselining the broker persistence (lossless today — the sim account is flat, 0 trades):

1. Stop backend.
2. (this amendment) `broker.yaml initial_capital: 30000`.
3. Clear `broker_events` + `broker_snapshots` (+ `equity_points` for clean history) in Mongo `quantmind`.
4. Restart in `simulation_auto` (`FEISHU_INTERACTIVE_ENABLED=false`) → `recover_state` finds no snapshot → seeds fresh ¥30k.
5. First auto-trade attempt: next 09:35 Line-1 cron (today's already fired).

## Reversible

Another amendment + the same re-baseline procedure.

Raising capital to the Normal tier sidesteps this for the test; if a genuinely small real account is targeted later, the small-tier allocation (deploy_fraction floor / single-lot allowance / ETF tilt) needs a dedicated amendment so it can actually trade.
