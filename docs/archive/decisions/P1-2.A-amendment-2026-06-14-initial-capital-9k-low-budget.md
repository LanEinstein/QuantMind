## 2. 修订后

### 2.1 配置改值

- `config/broker.yaml`: `mock.initial_capital: 100000 → 9000` + 注释更新(¥9 千 = Small 档,P0-7 三连**不**严格适用,见下)。
- 其余 broker.yaml(commission/stamp_tax/slippage_by_board/transfer_fee/min_commission)**全不变**。
- `BrokerScheduler.__init__(initial_capital=100_000.0)` 代码默认 + `main.py` 注入**不改**:单一真相源仍是 `broker.yaml`,代码默认仅 fallback(且测试 `test_broker_scheduler.py:374` 断言的是该代码默认值,不读真实 config)。
- **档位语义**:¥9,000 < `budget_tiers.small_max_cash_yuan(10000.0)` → **Small 档**。
  - 可负担 universe = 低价股 1 手 + `etf_whitelist`(510300/510500/159949)。
  - `concentration_exception` **解锁**(仅白名单宽基 ETF + Micro/Small;个股永不享;RiskEngine 独立再校验,L-004)。
  - `max_lot_cost = cash × 15% = ¥1,350`(单股仍 ≤15%,但 ETF 可经豁免 >15%)。
  - `NO_COMPLIANT_TRADE` 仍为一等 outcome(无合规整手时,非 error 非 HOLD 副作用)。

### 2.2 全新账户重置剧本(**必须执行,非裸改 YAML**)

改本金 = **账户生命周期事件**(P0-1 §1.3 / 前序 amendment §2.2)。本次目标 = **全新 ¥9 千空仓账户**,且当前账户 0 真实持仓(无可保留),故采用**整账归档 + 回落 config 重新播种**路径(适配当前 go-live 自动 boot 流:`mode_router.switch_mode` 自动读 `account.initial_capital`,无手动传值钩子 → 必须先让账户从 config 重新播种,新本金才能进入持久态):

1. **停服**(owner)—— 优雅停止运行实例。
2. **归档旧账户**(可逆,非删除)—— 将 `broker_events` + `broker_snapshots` **rename** 为带日期的归档集合(如 `broker_events_archive_20260614` / `broker_snapshots_archive_20260614`)。整条 append-only 事件日志原样保全(append-only 8 红线不破:归档=整账迁移,非逐事件 mutate/delete);可随时 rename 回滚。
3. **改 config**(本 amendment §2.1)—— `initial_capital: 9000`。
4. **重启**(owner)—— `recovery.py` 见无 `broker_events`/`broker_snapshots` → 从 `config.initial_capital=9000` 播种全新空仓账户;`resolve_durable_mode` 无 `MODE_SWITCH_RESET` 事件 → 返回 `SIMULATION_AUTO` → 启动期 acceptance gate 通过 → sim→feishu 切换,`switch_mode` reset 读取**新播种的 `account.initial_capital=9000`** → 烤入全新 seq-1 `MODE_SWITCH_RESET(to_mode=feishu, initial_capital=9000)`。
5. **复验**(Claude 只读)—— 镜像 = `9000 / 0 仓`、`initial_capital` 基线 = 9000(pnl 从 0 起)、tier=Small、`durable_mode` 自洽(此后重启 no-op)。

> **与前序 §2.2 的差异**:前序在已有账户上手动 `reset_to_snapshot(新本金)`;本次因 go-live 自动流读 `account.initial_capital`,改走「归档→回落 config 重播种」让新本金自然进入生命周期。两者终态等价(镜像=新本金/空仓),均不直接 mutate broker 内部状态。
>
> **若 owner 改为「保留真实持仓」**:则不归档,而是重启后走一轮初始对账(`RECON-{date}`)按 owner 实际持仓对齐镜像(fail-closed 对账精神,P0-5)。本次 owner 明确选「干净起步」→ 走归档路径。

### 2.3 安全核心不变

- MockBroker 单一镜像;覆盖必经 `reset_to_snapshot`(归档路径下由 go-live `switch_mode` 调用,非直接 mutate `_cash`/`_positions`/`_trades`)。
- append-only broker_events 8 红线不破(归档=整账 rename 迁移,旧日志保全可回滚)。
- config runtime 不可改 + hot-reload 禁用;本次改 = git diff + 本 amendment + 重启(+ §2.2 归档剧本)。
- 永禁真实下单;¥9 千是**模拟盘镜像额度**,非真实资金。
- PIT 可复现:新账户从 config 播种,seq-1 起全新 append-only 时间线,replay 自洽(R0 §3)。
